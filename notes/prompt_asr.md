# 功能与布局
你可以参考notes目录下的storm teleprompter plus的思维导图（同目录下有之前其他agent编写的解析器）。
1. 语音识别框架：采用Sherpa-Onnx作为语音识别的核心引擎。
2. UI布局：
   1. 应用设置界面：（仅服务端）
      - 语音识别模型选择：提供子界面供用户选择不同的Sherpa-Onnx模型。
      - 模型下载与更新：提供按钮供用户下载或更新模型，支持自定义镜像加速，支持后台下载、下载进度管理、从本地导入。
      - 模型说明：在界面中提供模型的详细说明，包括适用场景、性能指标等。
      - 模型推荐：根据用户设备性能，推荐最适合的模型。（准确性和低延迟优先）
      - （高级）模型参数设置：提供高级设置选项，允许用户调整模型的参数以优化识别效果。
   2. 提词器界面：
      - 当用户选择“语音”模式时，启动语音识别功能。
      - 在提词器界面的下方控制栏处的上方使用与控制栏相似的样式显示实时识别的文本，并支持滚动显示。注意：识别的文本显示栏属于叠加层，与控制栏一起隐藏和显示。
      - 当提词器暂停时，语音识别功能也应暂停，以节省资源。
      - 在控制栏中显示麦克风电平指示器，以供用户检查麦克风状态。
3. 内部逻辑
   1. 后端处理：所有语音识别逻辑统一在服务端实现，客户端只负责接收服务端处理完成的当前字位置、识别结果和麦克风电平信息。
   2. 暂停时，语音识别功能暂停但是不清空已识别的文本，不通知后端卸载模型及框架。
   3. 服务端退出提词器播放界面后延迟20秒后卸载语音识别模型及框架，如果在这段时间内用户重新进入提词器播放界面并选择“语音”模式，则取消卸载操作以避免不必要的重复初始化资源消耗。
   4. 在用户选择“语音”模式时，客户端才应向服务端发送请求以启动语音识别功能，前端UI界面应显示加载提示，直到服务端返回语音识别功能已启动的确认信息。
   5. 退出应用程序时需要妥善处理语音识别模型及框架的卸载，确保资源释放和应用程序的稳定性。
