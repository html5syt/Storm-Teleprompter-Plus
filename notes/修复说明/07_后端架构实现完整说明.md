## 概述

后端架构改动实现了**思维导图**中规定的两个关键特性：

1. **多客户端连接警告** (`BackendServer` + `HomeLogic`)
   - 当有 2 个及以上客户端连接时，用户尝试退出应用会收到警告
   - 提醒用户正在有外部设备连接到本机后端

2. **远程后端 UI 隐藏** (`ConnectionProvider` + `HomePage` + `SettingsPage`)
   - 连接到远程后端时，隐藏本地稿件管理、ASR 模型选择、后端配置等
   - 保留应用主题、应用字体、关于等全局设置

### 改动位置 4: `lib/pages/home_logic.dart`

**`_checkMultiClientBeforeExit()` 方法:**
```dart
Future<void> _checkMultiClientBeforeExit(BuildContext context) async {
  if (!context.mounted) return;

  final connection = context.read<ConnectionProvider>();

  // 非本地模式直接允许退出
  if (!connection.isLocal) {
    if (context.mounted) Navigator.pop(context);
    return;
  }

  // 检查全局 BackendServer 中的客户端数
  final clientCount = globalBackendServer.clientCount;
  final hasMultipleClients = clientCount >= 2;

  if (hasMultipleClients) {
    await _showMultiClientWarning(context, clientCount);
  } else {
    if (context.mounted) Navigator.pop(context);
  }
}
```

**`_showMultiClientWarning()` 方法:**
- 显示 AlertDialog，说明有多个客户端连接
- 用户可选择"保留运行"或"强制退出"
- 显示当前连接数

## 架构设计说明

### 多客户端监控的设计考虑

**为什么使用定期检查而不是事件驱动？**
- WsServer 中没有客户端连接事件暴露给 BackendServer
- 定期检查 (1 秒) 是可靠且低开销的方案
- 足以满足"有用户退出前时足够反应"的需求

**为什么使用全局变量？**
- HomeLogic 是 StatefulWidget 的 mixin，不是 Provider
- 通过 context.read<Provider> 无法访问 BackendServer
- 全局变量是最快速的解决方案（生产中可考虑 GetIt service locator）

### 远程 UI 隐藏的设计考虑

**分层策略:**
1. 搜索栏: 本地特有功能，不适合远程（无本地数据）
2. 稿件列表: 显示提示而不是空列表（用户了解原因）
3. 新建按钮: 不允许本地创建（与远程数据同步困难）
4. ASR/后端配置: 仅本地后端需要（远程后端由远程管理）
5. 主题/字体: 保留（全局偏好设置）

## 已知限制

1. **客户端计数包括本机客户端**
   - BackendServer.clientCount 包含本机前端连接
   - 实际外部连接数 = clientCount - 1
   - 建议:内在 BackendServer 中加入 `externalClientCount` getter

2. **远程模式下的本地提词**
   - 当前实现隐藏本地稿件管理
   - 建议后续: 支持从本机创建临时稿件用于提词

3. **全局变量的生命周期**
   - globalBackendServer 与应用同生命周期
   - 应用关闭时自动释放
