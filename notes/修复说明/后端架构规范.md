# 后端架构规范检查

## 思维导图中的后端规范

### 一、本地后端（LocalBackend）

本地后端包含以下服务：

#### 1. 稿件管理（ArticleService）
- CRUD 操作
- 文件夹管理
- 导入导出打包

**当前实现**: ✅ 已实现
- 位置: `lib/backend/article_service.dart`
- WebSocket 消息处理已注册

#### 2. 提词器后端同步（TeleprompterSession）
- 稿件内容同步
- 当前字（实时更新）
- 初始提词器设置（本地临时更新）

**当前实现**: ✅ 已实现
- 位置: `lib/backend/teleprompter_session.dart`
- WebSocket 消息处理已注册

#### 3. 设置存储（SettingsService）
- 全局设置持久化
- 文章级覆盖设置持久化

**当前实现**: ✅ 已实现
- 位置: `lib/backend/settings_service.dart`
- WebSocket 消息处理已注册

#### 4. 语音识别（ASR）
- Sherpa-onnx 模型管理
- 本地语音识别
- 实时识别结果返回前端
- 实时对齐当前字并同步

**当前实现**: 🟡 部分实现
- 模型下载和加载: `lib/services/asr_service.dart`
- WebSocket 同步: 需要验证

#### 5. 前后端链接与打包
- 通过 WebSocket 连接
- 前端默认连接到本机已存在的后端，如未启动则在本地启动一个
- 改连接到远程后端时停止由自身持有的后端实例
- 本机后端在有外部（2及以上）连接时，退出程序需要进行警告
- 前端需要保留后端实例的引用，并在合适时机销毁

**当前实现**: ✅ 基本完成
- 位置: `lib/main.dart` (启动后端)
- 位置: `lib/providers/connection_provider.dart` (连接管理)
- 位置: `lib/backend/backend_server.dart` (后端生命周期)

**验证项**:
- [ ] 后端自动启动逻辑 - `main.dart` 第 20-22 行
- [ ] 本地连接逻辑 - `ConnectionProvider.connectToLocal()`
- [ ] 远程连接时停止本地后端逻辑 - 需要检查 `connectToRemote()`
- [ ] 多客户端连接时的警告 - 需要实现

## 后端启动流程验证

### 当前实现流程

```
main()
  ↓
BackendServer.start()
  ├─ ArticleService.init()
  ├─ SettingsService.init()
  ├─ WsServer.start(port)
  ├─ 注册消息处理器
  └─ 返回实际端口
  ↓
ConnectionProvider.connectToLocal(port)
  ├─ 创建 WebSocket 客户端连接
  └─ 订阅服务器消息
  ↓
Application UI Ready
```

**验证检查清单**:
- [ ] 后端是否在 main() 中被正确启动
- [ ] 所有服务的初始化顺序是否正确
- [ ] WebSocket 端口是否正确传给前端
- [ ] 前端是否能正确连接到本机后端
- [ ] 连接失败时是否有适当的错误处理

## WebSocket 协议规范检查

**文件**: `lib/backend/ws_protocol.dart`

### 消息类型

需要验证以下消息类型是否完整实现：

#### 连接相关
- ✅ `connectionPing` - 心跳
- ✅ `connectionPong` - 心跳回复

#### 稿件管理
- `articleList` - 获取稿件列表
- `articleCreate` - 创建稿件
- `articleUpdate` - 更新稿件
- `articleDelete` - 删除稿件
- `folderCreate` - 创建文件夹
- `folderDelete` - 删除文件夹

#### 提词器服务
- `teleprompterStart` - 开始提词
- `teleprompterPause` - 暂停提词
- `teleprompterStop` - 停止提词
- `teleprompterCharIndex` - 当前字索引更新

#### 设置同步
- `settingsGet` - 获取设置
- `settingsSet` - 设置更新

#### ASR 相关
- `asrStart` - 开始识别
- `asrResult` - 识别结果
- `asrStop` - 停止识别

## 改进建议

### 优先级 1（关键）
1. 实现"多客户端连接时的警告"机制
   - 在 `BackendServer` 中监控 `clientCount`
   - 当 `clientCount >= 2` 时，标记警告状态
   - 在用户尝试退出应用时显示警告对话框

2. 实现远程连接时的 UI 隐藏
   - 在 `ConnectionProvider.isRemote` 为 true 时隐藏相关 UI
   - 使用 Consumer 包装隐藏的部分

### 优先级 2（重要）
3. 验证 WebSocket 消息类型的完整性
   - 检查所有必需的消息类型是否已定义
   - 添加缺失的消息类型

4. 实现远程会话同步
   - 添加会话开始的推送消息类型
   - 实现自动稿件下载和设置同步

### 优先级 3（后续）
5. 增强错误处理
   - 后端启动失败的处理
   - 连接失败的重试机制
   - 消息序列化失败的处理
